# 报价库范围筛选设计

## 目标

在现有“历史报价库”页面增加“历史报价大厅 / 自用报价”范围筛选，让员工可以在全部历史方案和自己创建、复制保存的方案之间快速切换，同时继续使用年份、月份、目的地、行程类型、人数、预算和关键词筛选。

## 用户体验

- 页面顶部筛选区域增加一个紧凑的分段切换，选项为“历史报价大厅”和“自用报价”。
- 默认选中“历史报价大厅”，保持当前页面首次进入时展示所有历史报价的行为。
- 选中“自用报价”后，仅展示当前登录用户 `created_by` 等于其账号 ID 的历史报价。
- 切换范围后，现有筛选条件、关键词和分页参数继续保留；清空筛选会同时恢复到“历史报价大厅”。
- 结果区标题和总数继续沿用现有布局，不增加重复的页面入口或侧边栏菜单。

## 实现方案

- 使用 GET 参数 `scope` 表达范围：`all` 表示历史报价大厅，`mine` 表示自用报价；缺失或非法值统一按 `all` 处理。
- `QuoteController@index` 将 `scope` 纳入允许传递的筛选字段，并继续使用 `withQueryString()` 保留分页上下文。
- `QuoteFilter::history()` 先限制 `status = historical`，再根据已规范化的 scope 为 `mine` 增加 `where('created_by', $user->id)`；查询保持 Eloquent Builder，避免先加载全部数据再在浏览器过滤。
- 将当前用户以显式参数传入过滤服务，避免服务内部读取全局认证状态，便于单元/功能测试。
- Blade 页面通过白名单值渲染切换链接或表单字段，当前范围使用现有 panel/button 视觉语言，并保留无障碍的 `aria-pressed` 状态。

## 权限与边界

- 只允许活动用户访问报价库，沿用现有 `viewAny` policy。
- “历史报价大厅”仍只返回历史状态报价，不扩大到草稿。
- “自用报价”只改变所有者范围，不改变查看、复制、编辑和管理员删除权限；这些行为继续由 `QuotePolicy` 决定。
- 非法 scope、空 scope 和手工篡改查询参数不会绕过权限，也不会产生 500。

## 测试策略

- 增加功能测试：员工在 `scope=mine` 下只能看到自己的历史报价；其他员工的报价和非历史状态报价不会出现。
- 增加默认范围测试：缺失或非法 scope 时仍显示全部历史报价。
- 增加视图契约测试：页面渲染两个范围选项、当前状态和保留查询参数所需的字段。
- 保留现有全部报价筛选、分页、policy 和工作台视图测试，并运行完整 PHP 与 JavaScript 测试套件。

## 不在本次范围

- 不新增数据库字段或迁移。
- 不改变报价创建、复制、编辑、删除逻辑。
- 不把“自用报价”做成独立路由或独立页面。
