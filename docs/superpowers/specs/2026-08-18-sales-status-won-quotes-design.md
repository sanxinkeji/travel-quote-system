# 报价销售状态与已成交报价页设计

## 背景

报价库目前只表达技术生命周期（历史报价或草稿），无法区分报价是否仍在跟进、处于其他状态，或已经被客户确认成交。业务人员还需要一个只包含客户认可方案的页面，用于查看本月出报价数量、成交数量和成交额，并从高可信度的成交方案中二次筛选。

本次功能包括：

1. 为报价增加独立的销售状态：跟进中、其他、已成交，默认跟进中。
2. 历史报价列表第一列显示创建报价的账号姓名。
3. 左侧菜单新增“已成交报价”页面。
4. 已成交页按统计月份展示出报价数、成交数、成交额，并复用历史报价筛选能力。
5. 普通员工只能修改自己创建或复制保存的报价，管理员可以修改全部报价。

## 已确认的业务规则

### 两套状态互不混用

现有 `quotes.status` 继续表示技术生命周期：`historical` 或 `draft`。它参与历史列表范围、草稿访问权限和现有策略，不能改作销售状态。

新增 `quotes.sales_status` 表示销售跟进状态，允许值为：

- `following`：跟进中
- `other`：其他
- `won`：已成交

新建报价和历史导入数据的 `sales_status` 默认都为 `following`。

### 成交时间和统计口径

新增可空的 `quotes.won_at` 时间字段：

- 从非成交状态切换为 `won` 时，记录当前时间。
- 从 `won` 切换回 `following` 或 `other` 时，清空 `won_at`。
- 重复保存同一个已成交状态不会刷新 `won_at`。

“本月出报价”按 `quotes.created_at` 统计，只统计技术状态为 `historical` 的报价；复制并保存的报价拥有新的创建时间，因此算作新报价。草稿不计入公开报价数量。

“本月成交数”和“成交额”按 `won_at` 统计，只统计技术状态为 `historical` 且 `sales_status=won` 的报价。成交额使用 `total_amount`，不重新计算行程明细。

统计月份默认为当前月份，可切换到任意月份；报价人筛选默认全公司，可选择具体账号。

### 权限

- 管理员可以查看和修改所有报价的销售状态。
- 普通员工可以查看全公司的历史报价，但只能修改自己创建或复制保存的报价状态。
- 未授权的状态更新返回 403，原状态不变。

## 页面与交互

### 历史报价库

保留现有“历史报价大厅 / 自用报价”范围切换和全部筛选项。报价表调整为：

1. 报价人：显示 `createdBy.name`，没有姓名时回退到用户名。
2. 报价名称。
3. 年月。
4. 目的地。
5. 行程。
6. 人数。
7. 人均。
8. 总价。
9. 主要项目。
10. 跟进状态。
11. 操作。

跟进状态显示为紧凑按钮或标签。对有权限的用户，点击后选择三个固定状态并直接提交；无权限时仅显示不可编辑标签。状态更新成功后回到当前筛选页面并显示成功提示。

原有查看、直接使用、复制并微调、管理员删除按钮继续保留图标和悬停提示。列表仍保持单行显示、不启用左右滚动；较长的报价名称和主要项目使用省略号，完整内容通过 `title` 或现有提示机制可查看。

### 报价详情

在报价详情的基础信息区域显示销售状态。拥有修改权限时使用与列表相同的状态控件；无权限时显示只读标签。状态更新不影响原有编辑、复制和预览流程。

### 已成交报价

左侧工作台菜单新增“已成交报价”，与“历史报价库”并列。页面结构采用已确认的方案 A：

1. 页面标题和说明。
2. 统计月份选择器，默认当前年月。
3. 三个统计卡片：本月出报价、本月成交、成交额。
4. 报价人、行程年月、目的地、行程类型、人数、人均预算、关键词等筛选。
5. 只显示所选统计月份内成交的历史报价列表。

已成交列表复用历史库的筛选和操作能力，第一列显示报价人，列表中用成交日期代替状态列。点击查看、直接使用和复制微调的行为与历史库一致；删除仍只对管理员显示。

统计月份和列表条件使用 GET 参数保存，分页和筛选切换不会丢失条件。统计查询使用数据库聚合，列表查询使用现有 `QuoteFilter`，并预加载 `createdBy`、行程分组和项目。

## 后端结构

### 数据库

新增迁移，为 `quotes` 添加：

- `sales_status`：长度 20、默认 `following`、建立索引。
- `won_at`：可空时间戳、建立索引。

迁移时将现有记录统一写入 `following`。回滚只删除新增列，不触及原有报价数据。

### 模型和服务

`Quote`：

- 将 `sales_status`、`won_at` 加入可填充字段和类型转换。
- 增加销售状态常量/标签映射和查询作用域，避免在控制器中散落字符串。
- 保留 `createdBy` 关系供列表和统计页面显示账号姓名。

`QuoteManager`：

- 新建、复制和更新时保留当前销售状态。
- 通过统一的状态更新方法维护 `won_at`，避免普通报价编辑绕过时间规则。

`QuoteFilter`：

- 保留现有历史库筛选。
- 增加成交页的销售状态、成交时间范围和报价人筛选组合，查询只返回历史且已成交记录。

### 路由和控制器

新增：

- `GET /won-quotes`：已成交报价页。
- `PATCH /quotes/{quote}/sales-status`：更新销售状态。

控制器先通过现有策略授权，再进行请求校验和事务更新；状态变更写入已有 `audit_logs`，记录旧值、新值和 `won_at` 变化。统计月份使用明确的起止时间，避免时区边界错误。

## 错误处理与兼容性

- 销售状态只接受三个枚举值，其他值返回验证错误。
- 统计月份必须是合法年月；非法值回退到当前月份并保留页面可用。
- `won_at` 为空的成交记录不会被统计；迁移不会把历史报价误判为成交。
- 没有关联用户姓名时，列表显示用户名或“未知账号”，不会导致页面报错。
- 现有技术状态、权限、复制保存新记录、管理员删除和导出/预览流程保持不变。

## 测试计划

新增或扩展以下测试：

1. 新建报价默认 `sales_status=following`，迁移后的旧记录也是 following。
2. 非成交切换成交写入 `won_at`，成交切回其他状态清空 `won_at`，重复成交不刷新时间。
3. 管理员可修改任意报价；员工只能修改自己的报价；无权请求返回 403。
4. 历史报价列表第一列渲染账号姓名，缺姓名时回退用户名。
5. 成交页只返回历史且已成交的记录，并正确按成交月份、报价人和原有条件筛选。
6. 本月出报价、成交数和成交额的聚合结果正确，跨月创建/成交场景不串月。
7. 分页和筛选参数在历史库、成交页之间保持。
8. 运行完整 PHPUnit 测试集和 JavaScript 测试集，确认原有工作流无回归。
